# Решения исполнителя плана 2026-11-01-contacts-extras

Формат: решение — почему — цена ошибки. Собрано из журнала исполнения (subagent-driven development).

- Файл, который не ZIP и не vCard, но содержит байт NUL, — `UnsupportedFormat` (двоичный файл), вдобавок к правилу «нет непустых заголовков» — тест плана ждал отказа на нулевых байтах, а одно правило про заголовки этого не давало — cost: CSV с байтом NUL отклоняется.
- Сбой поиска дублей после сохранения не превращает созданную запись в 500: ошибка пишется в лог, ответ 201 с `possibleDuplicates: []` — иначе повтор запроса создал бы дубль — cost: сбой поиска неотличим от «дублей нет».
- Список пар дублей считается поиском кандидатов по каждой живой записи с разбивкой на страницы в памяти; стоимость записана в коде, set-based запрос — в бэклоге — правила кандидатов не дублируются — cost: медленный `/duplicates` на больших workspace.
- Организация, найденная по названию, совпадает, только если у неё NIP пуст или равен NIP строки; другой NIP — создаётся новая организация — две фирмы с одним названием и разными NIP разные — cost: none.
- Значение перечисления вне вариантов поля при импорте — предупреждение, поле пропускается (пробный прогон и запись совпадают) — иначе пробный прогон показывал `create`, а запись — ошибку — cost: такие значения теряются, а не роняют строку.
- Приняты как есть: ключ сопоставления, которого нет среди заголовков, — ошибка сопоставления; повтор заголовка — ошибка, только если он сопоставлен; контакт без имени получает заголовком первый адрес; несколько организаций с одним названием — берётся самая старая с предупреждением — разумное прочтение, спецификация молчит — cost: none.
- Любая неожиданная ошибка строки при записи импорта даёт `error` с кодом `internal`, остальные строки продолжаются; причина передаётся в `onRowError` и пишется в лог маршрутом — §7.3 «ошибка строки не останавливает остальные» — cost: при отказе БД отчёт из одних ошибок вместо исключения.
- XLSX, у которого по центральному каталогу ZIP суммарный распакованный размер больше 50 МБ, отклоняется 413 `import_too_large` до загрузки в `exceljs` — 5 МБ файла превращались в ~1,7 ГБ памяти — cost: огромная разреженная книга отклоняется; защита опирается на каталог ZIP (подделка каталога — в бэклоге).
- vCard 2.1 с `ENCODING=QUOTED-PRINTABLE` (экспорт Android) декодируется с учётом `CHARSET`; свойства в BASE64 пропускаются — спецификация называет 3.0/4.0, но экспорт Android — частый случай для польских имён, а тихая порча недопустима — cost: none.
- Долгий импорт за Cloudflare Tunnel (таймаут 100 с, 5000 строк — минуты) в 2b не решается: решение до развёртывания — фоновая задача импорта на pg-boss или ограничение/разбиение — поведение верное, мешает только прокси — cost: большие импорты за туннелем получат 524, пока нет worker.
- Строка `create` без единого адреса получает предупреждение «нет адреса — повторный импорт создаст контакт снова»; README поправлен — идемпотентность импорта держится на адресах и NIP — cost: none.
- Финальная волна исправлений взяла также: отказ обновления по реестру при сменившемся NIP (409), лог причины 502, индекс в проверке уникальности NIP, предупреждение о незаписанных колонках найденной организации, лимиты multipart (400), `searchHits` только в транзакции, заметки README — cost: none.
- Развёртка свёрнутых строк vCard после финальных исправлений стала квадратичной (подобранный файл в 5 МБ мог надолго занять процессор), а NIP из реестра сравнивался без нормализации — по процессу вторая волна исправлений не запускается, поэтому вынесено на решение пользователя; пользователь одобрил исправление до слияния — развёртка линейна (100 тыс. строк: 24,6 с → 0,12 с), NIP сравнивается нормализованным — cost: none.
